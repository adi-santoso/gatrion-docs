Resource Users merepresentasikan akun dalam platform contoh.

## Daftar user

<ApiEndpoint
  method="GET"
  url="/v1/users"
  apiBase="https://api.example.com"
  queryParams={{ limit: "20" }}
  headers={{ Authorization: "Bearer $API_TOKEN" }}
/>

### Query parameter

| Nama | Tipe | Wajib | Deskripsi |
| --- | --- | --- | --- |
| `limit` | integer | Tidak | Jumlah hasil, dari `1` sampai `100` |
| `cursor` | string | Tidak | Cursor dari response sebelumnya |
| `status` | string | Tidak | Filter `active` atau `disabled` |

### Response

```json
{
  "data": [
    {
      "id": "usr_01J8Z6M4K2",
      "email": "ada@example.com",
      "name": "Ada Lovelace",
      "status": "active"
    }
  ],
  "next_cursor": null
}
```

## Buat user

<ApiEndpoint
  method="POST"
  url="/v1/users"
  apiBase="https://api.example.com"
  headers={{ Authorization: "Bearer $API_TOKEN", "Content-Type": "application/json" }}
  body={{ email: "ada@example.com", name: "Ada Lovelace" }}
/>

<Callout type="warning" title="Idempotensi">
  Kirim header `Idempotency-Key` saat mengulang create request agar tidak membuat user duplikat.
</Callout>

## Error

| Status | Kode | Arti |
| --- | --- | --- |
| `400` | `invalid_request` | Request body tidak valid |
| `401` | `unauthorized` | Bearer token tidak ada atau invalid |
| `409` | `email_exists` | Email sudah digunakan |
| `429` | `rate_limited` | Ulangi setelah durasi `Retry-After` |

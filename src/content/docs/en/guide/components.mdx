Components are globally injected into MDX. Use them directly — **never add import statements to a content file**.

## Callouts

<Callout type="note">Use notes for neutral context or supporting information.</Callout>
<Callout type="tip">Use tips for helpful shortcuts and recommended practices.</Callout>
<Callout type="important">Use important callouts for information readers must not miss.</Callout>
<Callout type="warning">Use warnings for risky actions or likely mistakes.</Callout>
<Callout type="caution">Use caution for destructive or irreversible actions.</Callout>

```mdx
<Callout type="tip" title="Optional custom title">
  Markdown **works** inside the component.
</Callout>
```

## File trees

<FileTree>
  <File name="src" type="folder" />

  <File name="Button.tsx" depth={2} description="Reusable button" highlight />

Depth is clamped from `0` to `12`, so malformed agent output cannot push a row outside the component.

## Code blocks

Use standard fenced code. Shiki handles syntax highlighting and the theme adds a language label and copy button.

```ts
type User = {
  id: string;
  name: string;
};

const greeting = `Hello, ${user.name}`;
```

Template literals and `${expressions}` are safe because code is Markdown, not a JSX prop.
